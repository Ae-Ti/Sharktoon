# 생성 파이프라인 인계 — 태일(B) → 웅싯(A)

> **상태 (2026-09-19)**: 아래 A·B·C 는 웅싯이 처리했다(`feat/generation-pipeline`, 아직 미푸시).
> D(게시물 패키지)만 남았다. 처리 내용은 `2026-09-18_생성파이프라인과컷편집기_웅싯.md`.
> 이 문서는 인계 당시 기록으로 남긴다.

관통 테스트를 해보니 화면은 끝까지 이어지는데 인스타툰이 실제로 만들어지지는 않는다.
막힌 지점 네 개 중 **태일 몫 두 개는 끝났고**, 남은 둘은 웅싯 영역이다.

## 태일이 끝낸 것 — 바로 쓰면 된다

### 1. 회차 컨텍스트

온보딩에서 받은 사연이 이제 실제 회차로 저장된다. `/onboarding/story` 에서 "콘티 만들기"를 누르면
시리즈와 1화를 만들고 `/episodes/<새 id>/storyboard` 로 이동한다.

```ts
import { loadEpisodeContext } from "@/features/platform/episode";

// 서버 컴포넌트에서
const ctx = await loadEpisodeContext(episodeId);
// ctx: { episodeId, seriesId, seriesTitle, number, story, cutCount, rule, assets }
```

`StoryboardScreen` 과 `GenerationScreen` 이 `MOCK_STORYBOARD` 대신 이걸 받으면
**사용자가 실제로 쓴 사연**으로 콘티가 만들어진다. 지금은 무엇을 입력하든 "퇴근 10분 전에…" 가 나온다.

`rule` 에는 그림체·기본 컷 수·비율·말투·고정 해시태그가, `assets` 에는 그 시리즈에 고정된
캐릭터·장소·소품이 들어 있다. 생성 호출에 그대로 실으면 된다.

### 2. 크레딧 3단

서버 액션으로 감싸 두었다. Supabase 키가 없어도 목 원장에서 실제로 잔량이 움직인다.

```ts
import {
  holdCreditAction,
  commitCreditAction,
  refundCreditAction,
} from "@/features/platform/actions";
import { CREDIT_COST } from "@/contracts/credit";

// 생성 요청 직전
const held = await holdCreditAction({
  amount: CREDIT_COST.cutImage * cuts.length,
  reason: "cut_image",
  jobId,
});

if (!held.ok && "code" in held && held.code === "insufficient") {
  // 버튼을 disabled 로 막지 말고 여기서 시트를 연다
  // <CreditSheet required={held.required} available={held.available} ... />
}

// 컷이 성공하면
await commitCreditAction(held.holdId);
// 컷이 실패하면 — 자동 환불이고 사용자에게 보이게 알린다
const r = await refundCreditAction(held.holdId, "3번 컷 실패");
```

`CreditSheet` 는 `@/features/platform/components/CreditSheet` 에 있다.

## 웅싯이 해야 하는 것

### A. `ImageGenerator` 자리표시자 구현 (우선순위 1)

지금 인터페이스만 있고 구현체가 없다. **모델 선정(오픈 이슈 1)을 기다리지 말고 자리표시자를 먼저
만들어 달라.** 컷 번호와 대사가 찍힌 이미지를 지연 시간까지 흉내내서 돌려주는 것이면 충분하다.

이게 있어야 확인되는 것:

- 컷 단위 진행률이 실제로 차오르는지
- 실패 컷 재시도가 큐에서 제대로 도는지
- 크레딧 hold → commit / refund 가 실제 흐름에서 맞물리는지

**생성 실패와 환불이 분쟁 나는 지점**이라 모델 없이 먼저 검증해 두는 게 값이 크다.
실패를 확률로 섞어서 (예: 10%) 돌려주면 실패 경로까지 같이 본다.
모델이 정해지면 이 구현만 갈아끼우면 된다.

### B. 콘티·생성 화면을 회차 컨텍스트에 연결 (우선순위 2)

위 `loadEpisodeContext` 로 `MOCK_STORYBOARD` 를 대체한다. 화면 구조는 그대로 두고 데이터 출처만 바꾸면 된다.

### C. 게시물 패키지 화면 (4.1) — 아직 없다

와이어프레임에는 있는데 코드에 화면 자체가 없다. 캡션 3안(짧게·감성·유머), 해시태그 15~25개
(시리즈 고정 + 화별 동적 구분), 첫 댓글, 캐러셀 ZIP 내보내기.

시리즈 고정 해시태그와 말투는 `ctx.rule.fixedHashtags`, `ctx.rule.tone` 에 있다.

**여기까지 있어야 "인스타에 올릴 파일을 받는다"가 완성된다.** 클로즈드 베타 범위이고,
첫 게시 완주율을 재려면 반드시 필요하다.

### D. 크레딧 호출 붙이기

지금 생성 버튼은 "6크레딧"이라고 표시만 하고 원장을 부르지 않는다. 위 2번 코드를 붙이면 된다.

## 남은 순서 제안

1. A(자리표시자 생성기) — 이게 있어야 나머지를 확인할 수 있다
2. D(크레딧 호출) — A 에 얹으면 바로 된다
3. B(컨텍스트 연결)
4. C(게시물 패키지)

1~2 만 되어도 "사연 입력 → 컷이 하나씩 차오름 → 실패 컷 재시도 → 크레딧 차감·환불 → 결과"
전체를 모델 없이 돌려볼 수 있다.
