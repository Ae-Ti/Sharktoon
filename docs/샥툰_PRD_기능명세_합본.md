## 1. 프로젝트 개요
---
### 한 줄 정의
AI 인스타툰 연재 서비스

### 제품 목표
그림을 못 그리는 일반인이 사연 한 줄로 5분 안에 첫 인스타툰을 게시하고, 일관된 캐릭터와 시리즈 맥락을 바탕으로 다음 화까지 지속 제작하도록 돕는다.

### 배경
기존 AI 이미지 생성 도구는 단발 결과물 중심이라 캐릭터 일관성, 편집 가능한 텍스트, 회차 운영과 게시 후 성과 활용이 어렵다. 인스타툰 제작자는 그림 실력과 제작 시간의 장벽 때문에 첫 게시와 연재 지속에 어려움을 겪는다.

### 사용자 문제
초보자는 사연을 인스타툰 문법에 맞는 콘티와 이미지로 전환하기 어렵고, 회차마다 캐릭터·배경·스타일이 흔들린다. 생성 후에는 전체를 다시 만들기보다 컷과 일부 요소만 수정하고, 게시용 캡션·파일·다음 화 소재까지 빠르게 준비할 수 있어야 한다.

### 해결 방안
소셜 로그인부터 캐릭터·사연·첫 화 결과까지 3단계 온보딩을 제공한다. 에셋과 시리즈 규칙을 고정 컨텍스트로 사용해 콘티·이미지를 생성하고, 레이어 기반 컷 편집·부분 재생성·게시용 내보내기·성과 기반 다음 화 제안을 하나의 연재 흐름으로 연결한다.

### 차별점
단발 이미지 생성기가 아니라 다음 화 제작을 중심으로 한 연재 운영 도구다. 텍스트는 이미지에 굽지 않는 벡터 레이어로 유지하고, 캐릭터·에셋·시리즈 규칙을 모든 회차에 고정 적용하며 컷·부분 단위 수정을 우선한다.

### 타겟 사용자
1차 사용자는 그림을 못 그리지만 인스타툰을 처음 올려보고 싶은 일반인으로, 짧은 사연은 있으나 콘티·그림·편집 경험이 부족하다. 2차 사용자는 연재로 팔로워를 확보한 크리에이터로, 성과 분석과 미디어킷·광고주 매칭을 통해 수익화 기회를 찾는다.

### 사용자 시나리오
사용자는 카카오 또는 구글로 로그인하고 셀카·특징 태그·텍스트 설명 중 하나로 캐릭터를 만들거나 기본 캐릭터를 선택한다. 사연을 입력해 콘티의 후킹·CTA를 수정한 뒤 에이전트 또는 한 컷 모드로 이미지를 생성하고, 편집기에서 텍스트·말풍선·일부 이미지 영역을 조정한다. 완성 화의 캡션과 해시태그를 복사하고 캐러셀 이미지를 내보낸 뒤, 시리즈 성과와 메모를 바탕으로 다음 화 소재를 제안받는다.

### 핵심 지표
첫 게시까지 완주율 40% 이상, 2화 생성률 30% 이상을 달성한다. 전체 재생성 대비 부분 재생성 사용 비율, 출석 체크 7일 연속 달성률, 유료 전환율, 미디어킷 생성 대비 광고주 매칭 성사율을 추적한다.

### 리스크
생성 지연·실패는 첫 게시 전 이탈과 크레딧 분쟁으로 이어질 수 있어 실패 컷 재시도와 자동 환불이 필요하다. 개인 이미지·저작권·미성년자 안전 문제, Instagram API 및 결제 정책 변화, 생성 결과의 캐릭터 일관성 저하를 관리해야 한다.

### 경쟁 분석 요약
국내 인스타툰 AI 생성 서비스는 OLLI, 인툰, 툰스툰스, 젠툰 등 4개 이상이 "텍스트→멀티컷 자동 생성 + 캐릭터 일관성"이라는 동일 공식으로 경쟁한다. 해외는 Dashtoon(LoRA 학습 기반 장편 일관성, 시드 투자 유치)이 선두이며 Anifusion·COMICPAD·Comistitch 등은 만화·웹툰 페이지 제작에 특화되어 인스타툰 규격과 한국어 조판에 약하다. 2025년 이후 이미지 모델의 레퍼런스 기반 캐릭터 고정 기능이 보편화되면서 생성 품질 자체는 평준화되었고, 장당 원가가 수십 원 수준으로 내려와 진입장벽이 낮아졌다.

각 서비스에서 확인한 장점은 본 제품에 흡수한다: 에셋·시리즈 관리와 한 컷/에이전트 모드 구분(젠툰), 인스타 업로드 본문·해시태그 생성(인툰), 나레이션 디자인 스타일·시리즈 단위 생성 규칙·애니메이션 변환(툰스툰스), 공개 피드와 미디어킷·광고주 매칭(OLLI), 1화 분량 무료 크레딧·워터마크·출석 체크(공통 요금 관행).

경쟁사 어디에도 없는 영역은 (1) 회차를 넘어가는 연재 운영(회차 타임라인, 에셋 참조 그래프), (2) Instagram 성과 회수 → 다음 화 제안 루프, (3) 텍스트를 이미지에 굽지 않는 벡터 레이어 편집, (4) 컷·부분 단위 재생성 우선 설계다. 본 제품은 이 네 가지를 핵심 차별점으로 삼는다.

### 페르소나
**페르소나 A — 첫 인스타툰을 올려보고 싶은 일반인 (1차 타겟)**
- 20대 후반 직장인. 회사·연애·반려동물 이야기 같은 짧은 사연은 많지만 그림을 그릴 줄 모르고, 다른 AI 툴은 "설정할 게 너무 많아" 첫 결과를 보기 전에 포기한 경험이 있다.
- 원하는 것: 오늘 저녁에 첫 게시물을 올리는 것. 캐릭터가 나와 닮았으면 좋겠고, 결과가 마음에 안 들면 그 컷만 고치고 싶다.
- 두려운 것: 요금제 결제 요구, 인스타툰 문법을 모르는 데서 오는 어색함, 다음 화에서 캐릭터가 달라지는 것.

**페르소나 B — 팔로워를 확보한 인스타툰 크리에이터 (2차 타겟)**
- 팔로워 1만~5만. 주 2~3회 연재하며 협찬 문의가 오기 시작했다. 제작 시간 단축과 반응 좋은 컷 패턴 파악, 협찬 제안서(미디어킷) 준비가 필요하다.
- 원하는 것: 시리즈 자산이 한 곳에서 관리되고, 게시 성과가 다음 화 기획에 자동으로 반영되며, 미디어킷을 몇 분 만에 만드는 것.
- 두려운 것: 독자에게 "AI로 만든 티"가 나서 반감을 사는 것, 저작물이 타 사용자에게 복제되는 것.

### 사용자 스토리
- 일반 사용자로서, 셀카 한 장으로 캐릭터를 만들고 사연 한 줄로 첫 화를 받아 보고 싶다. 그래야 오늘 바로 인스타에 올릴 수 있다.
- 일반 사용자로서, 첫 화 결과에서 마음에 안 드는 컷 하나의 표정만 바꾸고 싶다. 전체를 다시 만들면 크레딧과 시간이 아깝다.
- 일반 사용자로서, 캡션과 해시태그를 자동으로 받고 캐러셀 이미지를 순서대로 내보내고 싶다. 게시 준비에 시간을 쓰고 싶지 않다.
- 크리에이터로서, 등록한 캐릭터·장소·소품이 모든 회차에 자동 적용되길 원한다. 회차마다 캐릭터가 흔들리면 연재를 이어갈 수 없다.
- 크리에이터로서, 게시 성과를 보고 다음 화 소재와 썸네일 문구를 제안받고 싶다. 무엇이 반응이 좋았는지 감으로 판단하고 있다.
- 크리에이터로서, 시리즈 성과가 담긴 미디어킷을 링크로 공유하고 조건에 맞는 광고 제안을 받고 싶다.
- 광고주로서, 카테고리와 예산에 맞는 크리에이터에게 제안을 보내고 브랜드툰 결과물을 검토·승인하고 싶다.
- 운영자로서, 부적절한 생성 요청과 신고된 피드 콘텐츠를 처리하고 크레딧 환불 내역을 확인하고 싶다.

### 비목표 (Out of Scope, 1차 버전)
- 광고비 정산 중개 및 에스크로 결제
- React Native 등 별도 코드베이스의 네이티브 앱 (앱은 Capacitor 래핑으로 웹과 단일 코드베이스 유지)
- 타 SNS(스레드, 틱톡, 네이버 블로그) 직접 게시 연동
- 사용자 개인 그림체 LoRA 학습 (2차 검토 항목)
- 다국어 UI 및 해외 결제
- 이미지에 텍스트를 직접 렌더링하는 방식의 생성
- 다른 사용자의 캐릭터·저작물 복제 기능
- 사용자 간 실시간 협업 편집

|---|---|---|
| **클로즈드 베타** | 1장 온보딩, 2장 에셋·시리즈·콘티, 3장 생성·편집기, 4.1 게시물 패키지, 요금제 중 무료·출석 체크 | 초대 사용자 50명 중 첫 게시 완주율 40% 달성 |

| **정식 출시** | 5.1 릴스 애니메이션, 5.2 미디어킷·광고 협업, 크레딧 팩 판매, 웹·앱 동시 정식 출시 | 유료 전환율 목표 및 광고주 파일럿 3건 확보 |

앱 심사는 웹 출시 예정일 최소 3주 전에 제출한다. UGC·AI 생성 콘텐츠 앱 심사 대비로 신고·차단, AI 라벨, 콘텐츠 정책 링크를 심사 제출 빌드에 포함한다.

우선순위 기준: (1) 첫 게시 완주율에 직접 영향 → (2) 2화 생성률에 영향 → (3) 유료 전환·수익화 순으로 배치한다. 기능별 중요도(🔴🟡🟢)는 이 기준을 따른다.

### 비기능 요구사항
- **성능**: 콘티 생성 30초 이내, 6컷 이미지 생성 2분 이내, 첫 화 결과까지 5분 이내. 편집기 캔버스 조작은 60fps를 유지하고 자동 저장은 3초 디바운스로 처리한다.
- **처리량**: 동시 생성 요청 200건을 큐(Vercel Workflows 또는 Supabase pgmq)에서 처리하며 사용자별 동시 생성은 3화로 제한한다.
- **가용성**: 월 가용성 99.5% 이상. 생성 API 장애 시 큐에 보관하고 사용자에게 지연을 안내한다.
- **보안**: 소셜 로그인 토큰과 Instagram 액세스 토큰은 암호화 저장, 원본 이미지는 서명 URL로만 접근. 셀카 원본은 캐릭터 시트 생성 후 기본 삭제(사용자 선택 시 30일 보관).
- **데이터 보관**: 생성 이미지와 편집 데이터는 계정 유지 기간 보관, 탈퇴 시 30일 후 완전 삭제.
- **접근성·호환성**: 최신 Chrome·Safari·Edge 및 iOS 16+, Android 10+ 지원. 편집기는 데스크톱과 모바일 터치(핀치 줌, 드래그, 롱프레스) 모두 지원한다. 앱에서는 카메라(셀카 캐릭터), 푸시 알림(출석 체크·다음 화 제안), 갤러리 저장(캐러셀 내보내기) 및 인스타그램 앱 바로 열기를 네이티브 기능으로 제공한다.
- **관측성**: 생성 실패율, 평균 생성 시간, 크레딧 환불 건수, 단계별 온보딩 이탈률을 대시보드로 상시 모니터링한다.

### 의존성과 제약
- **이미지 생성 API**: 레퍼런스 이미지 기반 캐릭터 고정을 지원하는 모델을 1차로 사용하고 인터페이스로 추상화해 교체 가능하게 한다. 모델 정책(실존 인물·미성년자·타 IP 제한)을 서비스 필터와 이중으로 적용한다.
- **Instagram Graph API**: 비즈니스·크리에이터 계정만 인사이트 조회가 가능하므로 온보딩에서 계정 전환을 안내한다. 앱 심사(권한 승인)에 수 주가 소요될 수 있어 오픈 베타 일정에 반영한다.
- **결제**: 웹은 토스페이먼츠 심사 및 정기결제 승인이 필요하다. 앱에서 판매하는 크레딧·구독은 디지털 재화이므로 iOS는 Apple 인앱결제, Android는 Google Play 결제를 사용해야 하며 스토어 수수료(15~30%)가 발생한다. 세 결제 채널의 구독 상태와 크레딧 원장은 Supabase DB 한 곳에서 통합 관리하고, 스토어 구독 동기화는 RevenueCat 등 구독 관리 도구 사용을 검토한다. 구독 취소·환불 정책을 결제 전 고지한다.
- **앱 스토어 심사**: App Store·Play Store 심사에 수일~수 주가 소요된다. 소셜 로그인은 Capacitor 환경에서 네이티브 SDK 또는 커스텀 URL 스킴 딥링크로 처리하고 Supabase Auth 리다이렉트 설정을 앱용으로 분리한다.
- **법·정책**: AI 생성물 표시 의무, 저작권·초상권, 개인정보(셀카) 처리 방침, 광고 표기 규정(브랜드툰)을 준수한다.
- **라이선스**: 한글 폰트와 배경음은 상업 이용 가능한 라이선스만 번들한다.

## 1. 첫 화 제작 온보딩
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중

일반 사용자가 소셜 로그인 후 캐릭터와 사연을 입력하거나 건너뛰고 첫 인스타툰 결과까지 도달하는 제작 시작 영역이다. 온보딩은 캐릭터, 사연, 결과의 간결한 흐름과 기본값 생성을 포함하며, 프로필 작성·요금제 선택은 첫 화 결과 전 범위에서 제외한다.

**수용 기준:**
```
1. ○ 사용자는 카카오 또는 구글 로그인 후 진행 바가 있는 온보딩 흐름을 시작할 수 있다.
2. ○ 사용자는 캐릭터 또는 사연 단계를 건너뛰어 기본 캐릭터나 예시 사연으로 첫 화 결과를 생성할 수 있다.
3. ○ 첫 화 결과 전에는 이메일 인증, 프로필 작성, 요금제 선택을 요구하지 않는다.
```


### 1.1 3단계 온보딩과 캐릭터 만들기
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 일반 사용자 | **기기**: 웹

**기능의 근거**: 첫 게시 전 입력 부담을 최소화해야 첫 게시까지 완주율을 높일 수 있다.

일반 사용자가 소셜 로그인 후 셀카, 특징 태그, 텍스트 설명 중 하나로 캐릭터를 만들고 스타일 프리셋을 선택하는 기능이다. 건너뛰기와 기본 캐릭터를 제공하며 첫 화 결과에서만 시리즈 시작을 제안한다.

**성공 기준**: 온보딩 시작 사용자 중 첫 화 결과 도달률이 상승한다.

**개발 준비 슬롯**
- **표시**: - 온보딩 화면에는 현재 단계를 보여주는 진행 바를 표시한다.
  - 스타일 프리셋은 심플 라인, 파스텔, 굵은 선으로 제공한다.
- **비즈니스 규칙**: - 온보딩은 소셜 로그인, 캐릭터 만들기, 사연 입력, 첫 화 결과의 고정 흐름으로 제공한다.
  - 캐릭터 입력은 셀카 1장, 특징 태그 5개 이하, 텍스트 설명 중 하나를 사용한다.
  - 캐릭터 시트는 정면, 측면, 표정 4종, 전신 구성을 제공한다.

## 2. 시리즈 자산과 콘티 관리
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중

사용자와 크리에이터가 캐릭터·장소·소품·스타일 자산 및 시리즈 규칙을 관리하고 사연을 회차 콘티로 만드는 영역이다. 시리즈 컨텍스트와 자산 참조는 새 화에 자동 적용하며, 실제 이미지 생성·캔버스 편집은 이 범위에서 제외한다.

**수용 기준:**
```
1. ○ 사용자는 레퍼런스 이미지, 설명, 태그를 가진 자산을 라이브러리에서 관리할 수 있다.
2. ○ 새 화의 콘티 생성 시 선택한 시리즈의 자산과 규칙이 자동 반영된다.
3. ○ 사용자는 이미지 생성 전에 컷 순서, 추가·삭제, 대사를 수정할 수 있다.
```


### 2.1 에셋과 시리즈 관리
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 일반 사용자, 크리에이터 | **기기**: 웹

**기능의 근거**: 연재마다 자산이 흔들리는 문제를 막아 일관된 제작 경험을 제공한다.

사용자가 캐릭터, 장소, 소품, 스타일 프리셋을 카드형 라이브러리에 등록하고 이를 묶어 시리즈를 관리하는 기능이다. 새 화에는 시리즈 자산과 스타일을 자동 적용하며 회차 참조 관계를 확인할 수 있다.

**성공 기준**: 2화 이상 생성한 사용자의 시리즈 자산 재사용률이 상승한다.

**개발 준비 슬롯**
- **비즈니스 규칙**: - 캐릭터 시트는 모든 이미지 생성 호출에 고정 레퍼런스로 전달한다.
  - 직전 컷 출력물은 캐릭터 레퍼런스로 사용하지 않는다.
  - 에셋 변경 시 영향받는 회차를 표시한다.
- **데이터**: - 각 에셋은 레퍼런스 이미지, 텍스트 설명, 태그를 보유한다.
  - 시리즈는 에셋 세트, 스타일, 생성 규칙, 회차 목록을 보유한다.


### 2.2 사연 기반 콘티 생성
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 일반 사용자, 크리에이터 | **기기**: 웹

**기능의 근거**: 초보자가 인스타툰의 후킹 구조를 직접 설계하지 않아도 첫 화를 만들 수 있어야 한다.

사용자가 사연 한 줄부터 한 문단을 입력하면 컷별 장면, 등장인물, 감정, 대사, 나레이션, 카메라를 갖춘 콘티를 생성하는 기능이다. 생성 전 사용자는 컷 순서와 구성, 대사를 수정할 수 있으며 1컷 후킹과 마지막 컷 CTA를 선택한다.

**성공 기준**: 콘티 생성 후 이미지 생성으로 이어지는 전환율이 상승한다.

**개발 준비 슬롯**
- **동작**: - 사용자는 이미지 생성 전에 컷 순서를 변경하고 컷을 추가·삭제하며 대사를 수정할 수 있다.
- **결과**: - 콘티는 컷 번호, 장면, 등장인물, 감정, 대사, 나레이션, 카메라 정보를 구조화해 반환한다.
  - 첫 컷은 후킹 문구 3안을 제공한다.
  - 마지막 컷은 좋아요 유도, 다음 화 예고, 질문형 CTA를 포함한 3안을 제공한다.

## 3. 이미지 생성과 컷 편집
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중

사용자가 콘티를 에이전트 모드 또는 한 컷 모드로 이미지화하고, 컷별 레이어를 수정하는 제작 영역이다. 부분 재생성, 벡터 텍스트, 말풍선, 나레이션, 자동 저장을 포함하며 영상 변환과 게시 성과 분석은 제외한다.

**수용 기준:**
```
1. ○ 사용자는 전체 콘티 생성과 단일 컷 생성 모드를 같은 콘티에서 전환할 수 있다.
2. ○ 생성 진행률은 컷 단위로 표시되고 실패한 컷만 재시도할 수 있다.
3. ○ 사용자는 이미지에 굽지 않은 텍스트와 말풍선 레이어를 편집하고 마스크 영역만 부분 재생성할 수 있다.
```


### 3.1 콘티 기반 이미지 생성
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 일반 사용자, 크리에이터 | **기기**: 웹

**기능의 근거**: 첫 사용자는 빠른 전체 생성을, 숙련 사용자는 컷 단위 제어를 필요로 한다.

사용자가 동일한 콘티로 에이전트 모드 전체 생성 또는 한 컷 모드의 세부 프롬프트 생성 방식을 선택하는 기능이다. 시리즈 규칙과 에셋을 자동 주입하고 큐 기반으로 컷별 진행과 실패 재시도를 제공한다.

**성공 기준**: 생성 시작 후 완료율이 상승하고 생성 실패에 따른 이탈이 감소한다.

**개발 준비 슬롯**
- **표시**: - 생성 중 각 컷의 진행률을 표시한다.
  - 한 컷 모드에는 이 컷만 다시, 구도 유지하고 표정만 변경, 배경만 교체 동작을 제공한다.
- **비즈니스 규칙**: - 에이전트 모드는 콘티 전체를 한 번에 생성한다.
  - 한 컷 모드는 사용자가 컷별 프롬프트를 조정해 생성한다.
  - 생성 요청은 큐로 처리하고 실패한 컷만 개별 재시도한다.


#### 3.1.1 에이전트 모드 전체 생성

사용자가 확정한 콘티의 모든 컷을 한 번의 요청으로 생성하는 동작이다. 시리즈 규칙과 고정 에셋을 자동 반영하고 각 컷의 생성 상태를 보여주며, 개별 컷 수동 편집은 포함하지 않는다.
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 일반 사용자, 크리에이터 | **기기**: 웹

**개발 준비 슬롯**
- **선행조건**: - 사용자는 이미지 생성할 콘티와 시리즈 컨텍스트를 선택한다.
- **동작**: - 사용자가 전체 생성 요청을 제출하면 콘티의 모든 컷을 생성 큐에 등록한다.
- **결과**: - 생성 결과는 각 콘티 컷에 연결된 이미지로 저장한다.
  - 생성 완료된 컷은 편집기로 이동해 수정할 수 있다.
- **예외**: - 생성에 실패한 컷은 해당 컷만 재시도할 수 있다.
  - 실패한 생성 요청에 사용한 크레딧은 자동 환불한다.


#### 3.1.2 한 컷 모드 재생성

사용자가 특정 컷의 프롬프트를 조정하거나 제한된 수정 동작을 선택해 해당 컷만 생성하는 동작이다. 구도 유지·표정 변경 또는 배경 교체를 지원하며 다른 컷의 결과를 변경하지 않는다.
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 일반 사용자, 크리에이터 | **기기**: 웹

**개발 준비 슬롯**
- **트리거**: - 사용자가 특정 컷에서 이 컷만 다시, 구도 유지하고 표정만 변경, 배경만 교체를 선택한다.
- **동작**: - 사용자는 선택한 컷의 프롬프트를 직접 조정해 생성 요청을 제출할 수 있다.
  - 선택한 제한 수정 동작은 해당 컷의 생성 프롬프트에 반영한다.
- **결과**: - 새 결과는 선택한 컷에만 적용한다.
  - 사용자는 에이전트 모드와 한 컷 모드를 같은 콘티에서 전환할 수 있다.
- **비즈니스 규칙**: - 모든 생성 요청에는 시리즈 규칙과 고정 캐릭터 레퍼런스를 적용한다.


### 3.2 레이어 기반 컷 편집기
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 일반 사용자, 크리에이터 | **기기**: 웹

**기능의 근거**: 전체 재생성 대신 컷과 부분 단위로 수정해야 크레딧 낭비와 제작 부담을 줄일 수 있다.

사용자가 생성된 컷에서 배경·캐릭터 이미지와 말풍선·텍스트·나레이션·효과음 레이어를 편집하는 캔버스 기능이다. 부분 재생성, 실행 취소·다시 실행, 자동 저장을 지원하며 텍스트를 이미지에 직접 굽지 않는다.

**성공 기준**: 전체 재생성 대비 부분 재생성 사용 비율이 상승한다.

**개발 준비 슬롯**
- **표시**: - 말풍선은 일반, 생각, 외침, 속삭임을 포함해 12종 이상 제공한다.
  - 한글 폰트는 20종 이상 제공한다.
  - 나레이션 박스는 시리즈 스타일을 기본 적용하고 컷별 재정의를 허용한다.
- **비즈니스 규칙**: - 텍스트와 말풍선은 이미지와 분리된 벡터 레이어로 유지한다.
  - 사용자는 마스크 영역과 프롬프트로 해당 부분만 재생성한다.
  - 편집 내용은 자동 저장하고 실행 취소와 다시 실행을 제공한다.

## 4. 게시와 연재 성과 운영
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 기획 작성중

크리에이터가 완성 화를 인스타그램용으로 내보내고, 공개 피드와 Instagram 연동을 통해 연재 성과를 활용하는 영역이다. 캡션·해시태그 생성, 커뮤니티 상호작용, 성과 대시보드와 다음 화 소재 제안을 포함하며 광고비 정산은 제외한다.

**수용 기준:**
```
1. ○ 사용자는 화별 캡션 3안, 해시태그, 첫 댓글 텍스트를 생성하고 이미지 ZIP을 내보낼 수 있다.
2. ○ 사용자는 공개 피드에서 화를 게시하고 좋아요, 댓글, 팔로우 및 시리즈 구독을 사용할 수 있다.
3. ○ 연동된 Instagram 계정의 게시물 성과와 다음 화 소재 제안이 시리즈에서 제공된다.
```


### 4.1 인스타 게시물 패키지 생성
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 일반 사용자, 크리에이터 | **기기**: 웹

**기능의 근거**: 제작 완료 후 게시 준비 단계를 줄여야 첫 게시와 지속 게시를 촉진할 수 있다.

크리에이터가 완성 화에서 인스타그램 본문, 해시태그, 첫 댓글을 생성하고 캐러셀 이미지를 내보내는 기능이다. 캡션은 시리즈 말투 규칙을 따르며 복사와 ZIP 내보내기를 제공한다.

**성공 기준**: 완성 화 중 게시물 패키지 생성 비율이 상승한다.

**개발 준비 슬롯**
- **결과**: - 본문은 짧게, 감성, 유머의 3안으로 생성한다.
  - 해시태그는 대중 태그와 니치 태그를 혼합한 15개에서 25개로 생성한다.
  - 시리즈 고정 해시태그와 화별 동적 해시태그를 구분한다.
- **표시**: - 사용자는 결과를 원클릭으로 복사할 수 있다.
  - 캐러셀 이미지는 1:1 또는 4:5 비율로 ZIP 내보내기를 제공한다.


### 4.2 인스타 연동과 성과 피드백
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 크리에이터 | **기기**: 웹

**기능의 근거**: 게시 후 반응을 다음 화 제작에 반영해야 연재 지속률을 높일 수 있다.

크리에이터가 Instagram 비즈니스 또는 크리에이터 계정을 연동하고 회차별 성과를 시리즈 대시보드에서 확인하는 기능이다. 썸네일 A/B 결과와 사용자 메모를 활용해 다음 화 소재를 제안한다.

**성공 기준**: 성과 대시보드 사용자의 2화 생성률이 비사용자보다 높아진다.

**개발 준비 슬롯**
- **결과**: - 성과가 좋은 문구 길이, 구도, 색상 패턴을 다음 화 콘티 제안에 반영한다.
  - 매주 이전 화 반응과 사용자 메모를 기반으로 다음 화 소재 3개를 제안한다.
- **데이터**: - 대시보드는 게시물별 도달, 저장, 공유, 프로필 방문 수를 표시한다.
  - 썸네일 A/B는 첫 컷 2안의 게시 결과를 비교한다.


### 4.3 공개 피드와 커뮤니티
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 일반 사용자, 크리에이터 | **기기**: 웹

**기능의 근거**: 연재를 공개하고 반응을 얻는 경험은 제작 동기와 커뮤니티 참여를 강화한다.

사용자가 완성 화를 서비스 공개 피드에 게시하고 좋아요·댓글·팔로우·시리즈 구독으로 상호작용하는 기능이다. 다른 작품의 스타일 프리셋만 복제할 수 있으며 캐릭터와 저작물 복제는 허용하지 않는다.

**성공 기준**: 공개 피드 게시 사용자의 시리즈 구독과 재방문이 증가한다.

**개발 준비 슬롯**
- **동작**: - 사용자는 공개 피드에서 좋아요, 댓글, 팔로우, 시리즈 구독을 사용할 수 있다.
  - 사용자는 인기 시리즈와 신작 탭을 탐색할 수 있다.
- **권한 & 접근**: - 사용자는 다른 작품의 스타일 프리셋만 복제할 수 있다.
  - 사용자는 다른 사용자의 캐릭터와 저작물을 복제할 수 없다.

## 5. 크리에이터 수익화 지원
> **중요도**: 🟢 낮음 | **진행 상태**: ⚪ 기획 작성중

크리에이터가 애니메이션 화, 미디어킷, 광고주 제안과 브랜드툰 협업을 통해 수익화 기회를 준비하는 영역이다. 광고주와 크리에이터 연결 및 검토·승인 워크스페이스를 제공하되, 1차 버전의 광고비 정산 중개는 제외한다.

**수용 기준:**
```
1. ○ 사용자는 완성 화 또는 회차를 릴스 규격 MP4 애니메이션으로 만들 수 있다.
2. ○ 크리에이터는 성과 지표와 대표 화를 포함한 미디어킷을 PDF 또는 웹 링크로 생성할 수 있다.
3. ○ 광고주는 제안을 등록하고 크리에이터는 조건에 맞는 제안을 수락해 브랜드툰 워크스페이스를 열 수 있다.
```


### 5.1 릴스 애니메이션 제작
> **중요도**: 🟢 낮음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 크리에이터 | **기기**: 웹

**기능의 근거**: 영상 포맷 확장은 연재 콘텐츠의 활용 범위와 프로 요금제 가치를 높인다.

크리에이터가 완성 컷 또는 화 전체를 짧은 릴스 영상으로 변환하는 기능이다. 컷 전환, 말풍선 순차 등장, 나레이션 타이핑, 선택적 미세 모션과 배경음을 포함하며 게시 캡션 생성과 연결한다.

**성공 기준**: 프로 사용자 중 애니메이션 생성 기능 사용률이 상승한다.

**개발 준비 슬롯**
- **결과**: - 결과물은 9:16 비율, 15초에서 30초 길이의 MP4로 제공한다.
  - 사용자는 무료 라이선스 배경음 라이브러리에서 배경음을 선택할 수 있다.
  - 릴스용 캡션 생성 기능과 연동한다.


### 5.2 미디어킷과 광고 협업
> **중요도**: 🟢 낮음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 크리에이터, 광고주 | **기기**: 웹

**기능의 근거**: 연재 성과를 수익 기회로 연결하려는 성장 단계 크리에이터를 지원한다.

크리에이터가 시리즈 성과와 대표 화로 미디어킷을 만들고 광고주 제안을 수락해 브랜드툰 협업을 진행하는 기능이다. 브랜드 자산 등록과 광고주 검토·승인을 지원하되 플랫폼 정산은 제공하지 않는다.

**성공 기준**: 미디어킷 생성 대비 광고주 매칭 성사율이 상승한다.

**개발 준비 슬롯**
- **결과**: - 미디어킷은 시리즈 요약, 캐릭터 소개, 성과 지표, 대표 화 3개, 협업 이력, 연락처를 포함한다.
  - 미디어킷은 PDF와 웹 링크로 제공한다.
  - 광고 제안 수락 시 브랜드툰 워크스페이스를 개설한다.
- **비즈니스 규칙**: - 브랜드 로고, 제품 이미지, 컬러는 브랜드툰 자산으로 등록한다.
  - 브랜드툰에는 광고 표기 문구를 자동 삽입한다.
  - 플랫폼은 광고비 정산을 중개하지 않는다.

## 프로덕트 정책

### 1. 요금제와 크레딧 정책

크레딧 단위: - 이미지 1컷 생성은 1크레딧을 사용한다.
- 부분 재생성은 0.5크레딧을 사용한다.
- 애니메이션 1화 생성은 5크레딧을 사용한다.
- 스토리와 캡션 생성은 크레딧을 사용하지 않는다.

요금제 혜택: - 무료 요금제는 가입 시 8크레딧, 워터마크, 시리즈 1개, 피드·커뮤니티 이용을 제공한다.
- 베이직 요금제는 월 9,900원으로 200크레딧, 워터마크 제거, 시리즈 3개, 무제한 캡션·해시태그를 제공한다.
- 프로 요금제는 월 19,900원으로 600크레딧, 무제한 시리즈, 애니메이션, 성과 대시보드, 미디어킷, 광고주 매칭을 제공한다.
- 크레딧 추가 팩은 별도로 판매한다.

결제 채널: - 웹은 토스페이먼츠, iOS 앱은 Apple 인앱결제, Android 앱은 Google Play 결제를 사용한다.
- 세 채널의 구독 상태와 크레딧은 하나의 원장으로 통합하며 어느 채널에서 결제해도 웹·앱 모두에서 동일하게 이용한다.
- 앱 판매가는 스토어 수수료를 반영해 웹과 별도로 책정할 수 있으며, 가격 차이는 결제 화면에 고지한다.

출석과 이월: - 출석 체크는 하루에 1크레딧을 지급한다.
- 7일 연속 출석은 보너스 3크레딧을 지급한다.
- 미사용 크레딧은 다음 달에 50퍼센트만 이월한다.

실패 환불: - 생성 요청이 실패하면 해당 요청에 사용한 크레딧을 자동 환불한다.

이미지·부분 재생성·애니메이션 사용량과 구독 혜택을 정하는 서비스 공통 정책이다.

### 2. 콘텐츠 안전과 개인정보 정책

생성 제한: - 미성년자 캐릭터의 부적절한 생성 요청은 차단한다.
- 실존 인물과 타 지식재산권 캐릭터를 모방하는 생성 요청은 차단한다.
- 모든 생성물에는 AI 생성 메타데이터를 기록한다.

개인 이미지 처리: - 셀카 원본은 캐릭터 시트 생성 후 삭제하는 옵션을 기본으로 활성화한다.

공개 콘텐츠 보호: - 피드에 노출하는 AI 생성물에는 AI 생성 라벨을 표시한다.
- 다른 사용자는 스타일 프리셋만 복제할 수 있으며 캐릭터와 저작물은 복제할 수 없다.
- 사용자는 공개 피드에서 신고와 차단을 사용할 수 있다.

개인 이미지와 AI 생성 콘텐츠의 안전한 처리 및 저작권 보호를 정하는 서비스 공통 정책이다.

### 3. 광고 협업과 정산 범위

협업 범위: - 광고주는 카테고리, 예산, 희망 팔로워 구간으로 제안을 등록할 수 있다.
- 조건에 맞는 크리에이터에게 광고 제안을 노출한다.
- 크리에이터가 제안을 수락하면 브랜드툰 워크스페이스를 개설한다.

브랜드 콘텐츠: - 브랜드툰 워크스페이스는 브랜드 로고, 제품 이미지, 컬러를 자산으로 등록할 수 있다.
- 브랜드툰에는 광고 표기 문구를 자동으로 삽입한다.
- 광고주는 브랜드툰 결과물을 검토하고 승인할 수 있다.

정산 제외: - 1차 버전에서 플랫폼은 광고비 정산을 중개하지 않고 광고주와 크리에이터 연결까지만 제공한다.
- 결제 연동은 2차 버전 범위로 둔다.

광고주 매칭과 브랜드툰 협업에서 서비스가 제공하는 범위와 제외 범위를 정하는 정책이다.


## 부록

### A. 기술 스택과 아키텍처
- **웹·API**: Next.js(App Router) + TypeScript, Route Handlers/Server Actions로 API 구성, Zustand(클라이언트 상태), TanStack Query(서버 상태), react-konva(레이어 캔버스 편집기, 터치 이벤트 지원), Tailwind CSS
- **모바일 앱**: Capacitor로 동일 Next.js 코드베이스를 iOS·Android 앱으로 패키징. 네이티브 플러그인: Camera(셀카), Push Notifications(출석·다음 화 알림), Filesystem/Media(갤러리 저장), App Launcher(인스타그램 앱 열기), Deep Links(소셜 로그인 리다이렉트). PWA 매니페스트도 함께 제공
- **인증**: Supabase Auth — 카카오·구글 OAuth, 웹은 리다이렉트, 앱은 커스텀 URL 스킴 딥링크. Row Level Security로 사용자·시리즈·에셋 접근 제어
- **데이터**: Supabase PostgreSQL(서울 리전), Supabase Realtime으로 컷 단위 생성 진행률 푸시
- **스토리지·CDN**: Supabase Storage(이미지·영상·미디어킷). 생성 이미지와 피드 이미지는 Vercel을 거치지 않고 Storage CDN에서 직접 서빙하며 원본은 서명 URL로 보호
- **비동기 생성 파이프라인**: 생성 요청을 Vercel Workflows(또는 Supabase pgmq + Edge Function 크론)에 적재 → 워커가 이미지·LLM API 호출 → 결과를 Storage에 저장하고 GenerationJob 상태 갱신 → Realtime으로 클라이언트 반영. Vercel Functions는 fluid compute 기준 최대 800초(Pro), 장시간 작업은 Workflows 사용
- **애니메이션 렌더링**: 이미지→비디오 모델 API 호출과 ffmpeg 합성은 서버리스 외부의 별도 컨테이너(Fly.io/Railway 또는 AWS Lambda 컨테이너) 또는 영상 합성 API로 분리
- **외부 연동**: 이미지 생성 API(인터페이스 `ImageGenerator`로 추상화), LLM API(구조화 JSON 출력, 스키마 검증), Instagram Graph API, 토스페이먼츠 웹훅, Apple/Google 스토어 결제 검증(RevenueCat 검토)
- **배포·운영**: Vercel(웹·API, 서울 리전 함수), Supabase(관리형), GitHub Actions(웹 배포·앱 빌드), Fastlane 또는 EAS 계열 도구로 스토어 배포 자동화, Vercel·Supabase 로그 및 Sentry 오류 추적
- **확장 경로**: 생성 워커·큐가 무거워지면 워커만 Spring Boot(AWS ECS Fargate + SQS)로 분리. Next.js·Supabase·Capacitor는 유지되므로 앱과 프론트는 영향받지 않음

### D. 용어 정의
- **인스타툰**: 인스타그램 캐러셀(1:1 또는 4:5, 최대 10장)에 게시하는 짧은 컷툰
- **화(회차, Episode)**: 한 번에 게시하는 인스타툰 단위. 4~10컷으로 구성
- **컷(Cut)**: 화를 구성하는 개별 이미지 한 장
- **콘티(Storyboard)**: 이미지 생성 전 컷별 장면·대사·감정을 정의한 구조화 데이터
- **에셋(Asset)**: 캐릭터·장소·소품·스타일 프리셋 등 회차 간 재사용되는 자산
- **시리즈(Series)**: 에셋 세트, 스타일, 생성 규칙, 회차 목록을 묶은 연재 단위
- **에이전트 모드 / 한 컷 모드**: 콘티 전체를 한 번에 생성하는 방식 / 컷 하나씩 프롬프트를 조정해 생성하는 방식
- **부분 재생성**: 컷 내 마스크 영역만 프롬프트로 다시 생성하는 인페인팅
- **후킹 / CTA**: 첫 컷의 시선 유도 문구 / 마지막 컷의 행동 유도 문구
- **미디어킷**: 크리에이터의 시리즈 성과·대표 화·연락처를 담은 협찬 제안용 자료

### E. 2인 역할 분담
코드베이스가 Next.js + Supabase 하나이므로 프론트/백엔드가 아닌 **도메인 수직 분담**으로 나눈다. 각자 담당 기능의 화면·API·DB·테스트를 끝까지 책임진다.

**개발자 A — 웅싯: 생성 & 편집 (AI 파이프라인 오너)**
- 2장 콘티: 사연 → 컷별 JSON, 후킹 3안·CTA 3안, LLM 프롬프트·스키마 검증
- 3장 생성: `ImageGenerator` 인터페이스, 캐릭터 시트 생성(셀카/태그 → 시트), 레퍼런스 고정 전달, 에이전트/한 컷 모드, 생성 큐(Vercel Workflows 또는 pgmq), 실패 재시도·크레딧 환불 트리거
- 3장 편집기: react-konva 레이어 캔버스, 말풍선·나레이션 프리셋·효과음, 부분 재생성(마스크 인페인팅), 모바일 터치, 자동 저장
- 4.1 게시물 패키지: 캡션·해시태그 생성, 캐러셀 렌더링·ZIP 내보내기
- 4.2 성과 피드백 중 다음 화 제안·썸네일 A/B의 추천 로직
- 5.1 릴스 애니메이션: 이미지→비디오 API, ffmpeg 렌더링 컨테이너
- 콘텐츠 필터(실존 인물·미성년자·타 IP 차단)

**개발자 B — 태일: 플랫폼 & 성장 (제품 인프라 오너)**
- 1장 온보딩: Supabase Auth(카카오·구글), 3단계 온보딩 플로우, 건너뛰기, 앱 딥링크
- 2장 에셋·시리즈: 에셋 라이브러리, 시리즈·생성 규칙, 회차 타임라인, 참조 그래프, RLS 정책
- 요금제: 크레딧 원장, 출석 체크, 토스페이먼츠 + Apple/Google 인앱결제(RevenueCat), 구독 상태 동기화
- 4.2 인스타 연동: Graph API OAuth, 게시물 인사이트 수집, 대시보드(추천 로직은 A와 인터페이스 합의)
- 4.3 공개 피드: 게시·좋아요·댓글·구독, 신고·차단, AI 라벨
- 5.2 수익화: 미디어킷 생성, 광고주 매칭, 브랜드툰 워크스페이스
- Capacitor 앱: 카메라·푸시·갤러리 저장·인스타 앱 열기, 스토어 심사 제출
- 운영: 관리자 화면, 모니터링(생성 실패율·온보딩 이탈률), Sentry, CI/CD·배포

**공통 (착수 첫 주에 함께 확정)**
- DB 스키마 전체(부록 B), 특히 두 사람의 접점인 `GenerationJob`·`Credit`·`CreditTransaction`
- 디자인 시스템·공통 컴포넌트, 라우팅 구조
- API 계약: A가 "생성 요청/결과" 인터페이스를, B가 "크레딧 차감/환불" 인터페이스를 먼저 고정
- 코드 리뷰는 교차로 수행

**단계별 담당**
| 단계 | A (웅싯) | B (태일) |
|---|---|---|
| 클로즈드 베타 | 콘티 → 생성 → 편집기 → 내보내기 | 온보딩 → 에셋·시리즈 → 무료 크레딧·출석 → 관리자 |
| 오픈 베타 | 부분 재생성 고도화, 추천 로직 | 결제 3채널, 인스타 연동, 피드, 앱 심사 |
| 정식 출시 | 릴스 애니메이션 | 미디어킷·광고주·브랜드툰 |

분담 근거: A의 영역은 프롬프트·모델 실험이 많아 반복 주기가 짧고, B의 영역은 결제·스토어·API 심사처럼 외부 리드타임이 길어 일찍 착수해야 한다. 성격이 달라 병렬 진행에 유리하며, 클로즈드 베타 시점에 A의 첫 화 생성과 B의 계정·에셋이 합쳐지면 바로 첫 게시 완주율을 측정할 수 있다.
