- 프로필, 크레딧 원장, 시리즈·생성 규칙·에셋·회차·참조, 운영자 집계
- **크레딧은 `hold → commit / refund` 3단.** hold에서 소모 거래를 기록해
  `sum(credit_transactions) == credit_accounts.balance`가 항상 성립한다.

- 원장 테이블은 RLS로 읽기만 열고, 변경은 `security definer` 함수로만 간다
- 오류 코드: SK001 크레딧 부족 / SK002 중복 정산 / SK003 중복 출석 / SK004 운영자 아님
- 로컬 Postgres 18에 실제로 적용해 검증. 이 과정에서 `attendance_check_in`의
  컬럼·출력변수 이름 충돌을 발견해 수정

- 처리방침은 셀카 처리(기본 즉시 삭제), 국외 이전, 법정 보관기간, 보호책임자, 권익침해 구제까지 채웠다

### 테스트와 CI

- `npm run check:repo` — 저장소 동작 25항목
- SQL 테스트 3종 — 원장 정합, RLS, 운영자 권한
- CI에서 타입체크·린트·빌드 + Postgres 17 컨테이너에 마이그레이션 적용 후 SQL 테스트까지
- `npm run dev:mock` / `dev:real` — 목과 실 테스트를 따로 돌린다. 로컬 Supabase 스크립트 포함

### 테스트에서 잡은 문제 5건 (전부 수정)

1. **회차 id 충돌** — `Date.now()` 기반 id라 같은 밀리초에 만든 두 회차가 같은 id를 받아
   앞 회차의 사연이 덮어써졌다. 사용자 눈에는 "방금 쓴 사연이 지난 회차 것으로 바뀌는" 현상
2. 모달 제목 id 중복 — `aria-labelledby`가 엉뚱한 제목을 가리킴
3. 홈의 "이어서 만들기"가 특정 회차로 하드코딩
4. 첫 화 결과 화면이 어디서도 도달 불가 — 온보딩 4단계가 끊겨 있었다
5. 크레딧 delta가 계속 붙어 있어 잔량과 헷갈림
