## 1. 콘티 생성 (PRD 2.2)

사연 텍스트 → 컷별 구조화 JSON. `claude-opus-5`, adaptive thinking, effort medium.

**스키마가 곧 계약이다.** Zod 스키마 하나를 `zodOutputFormat` 으로 모델에 넘기고
`messages.parse()` 로 받는다. 모델이 필드를 빠뜨리거나 종류를 지어내면 파싱에서 걸린다.
PRD 가 요구한 "LLM 프롬프트·스키마 검증"이 이 한 줄로 닫힌다.

**인스타툰 문법을 프롬프트에 적었다.** 1컷에서 멈추면 나머지는 아무도 안 본다,
중간 컷은 감정이 한 번 꺾여야 한다, 장면은 그릴 수 있는 것만 쓴다("후회했다"가 아니라
"현관에 신발도 안 벗고 주저앉은"). 이걸 아는 사람은 그냥 아는데 초보자는 모른다 —
그게 이 제품이 존재하는 이유라 모델에 떠넘기지 않았다.

**사연은 프롬프트 맨 뒤에 둔다.** 앞에 두면 뒤따르는 지시를 사연의 일부로 읽는 경우가 있다.
시스템 프롬프트에는 `cache_control` 을 걸었다 — 요청마다 같은 접두사라 캐시가 산다.

`ANTHROPIC_API_KEY` 가 없으면 목 콘티를 준다. 태일의 `getRepository()` 와 같은 방식이라
키 없이도 화면·플로우 전체를 만들 수 있다.

**id 는 서버가 매긴다.** 모델이 짓게 두면 회차끼리 충돌한다.

## 2. 이미지 생성 파이프라인 (PRD 3.1)

**hold 를 컷마다 건다.** 이게 제일 중요한 결정이다. 잡 단위로 한 번에 잡으면
"6컷 중 4컷 성공"에서 얼마를 돌려줘야 하는지가 원장에 남지 않는다.
컷마다 hold → 성공 commit / 실패 refund 로 닫으면 원장만 보고 정산이 끝난다.

**진행률은 80%에서 멈춰 세운다.** 모델이 중간 진행률을 주지 않아 추정치를 올리는데,
안 끝났는데 100%를 보여주면 멈춘 것처럼 보이는 것보다 나쁘다.

컷 2개씩 동시 생성, 실패한 컷만 재큐, 성공한 컷은 건드리지 않는다.

| 이슈 | 미정 항목 | 우회 |

| 1 | 1차 이미지 모델 | `ImageGenerator` 뒤에 `MockImageGenerator`. 정해지면 이 파일만 안 쓰면 된다 |

목 생성기는 4컷째를 첫 시도에만 실패시킨다. 실패·환불·재시도 경로가 눈에 보여야
그 화면이 제대로 만들어졌는지 알 수 있어서고, `SHARKTOON_MOCK_FAIL_CUTS=""` 로 끈다.

## 3. 콘텐츠 필터

PRD 는 "모델 정책과 서비스 필터를 이중으로 적용한다"고 요구한다. 3층으로 만들었다.

1. **규칙 필터** (`safety/rules.ts`) — 모델 호출 **전에** 돈다. 크레딧을 잡기 전에 막아야
   왕복이 없다.
2. **LLM 판정** — 콘티 응답의 `safety` 필드. 규칙을 통과했지만 모델이 막는 경우.
3. **이미지 모델 자체 정책** — 우리가 통제하지 않는다.

**실존 인물은 이름 목록으로 잡지 않는다.** "실제 사람을 지목하는 말투"로 잡는다.
이름 목록은 관리가 불가능하고 동명이인 오탐이 크다. 목록을 늘려 정확도를 올리려 들지 말고,
오탐이 나면 빼는 쪽으로 쓴다 — 이건 그물이지 자물쇠가 아니다.

**미성년자 등장 자체는 막지 않는다.** 학생이 나오는 인스타툰은 흔하다.
부적절 묘사와 겹칠 때만 막고, 그때는 문구도 더 좁은 사유로 바뀐다.

필터는 세 곳에 걸린다: 사연 입력, 컷 장면(사용자가 직접 고칠 수 있으므로), 한 컷 모드 프롬프트.

## 4. 컷 편집기 (PRD 3.2)

정적 레이아웃 → react-konva 로 실제 조작. 설계의 핵심 두 가지다.

**좌표는 전부 컷 이미지 원본 1080px 로 들고, 화면 배율은 Stage scale 로만 준다.**
확대해도 레이어 값이 안 흔들리고, 내보낼 때 원본 배율로 그대로 그린다.
화면 픽셀로 저장하면 창 크기가 다른 기기에서 열고 저장하는 순간 레이아웃이 밀린다.

**드래그 한 번은 이력 한 칸이다.** 조작 중에는 `preview` 로 현재 값만 바꾸고 이력에
쌓지 않는다. 안 그러면 실행 취소를 60번 눌러야 원위치가 된다. 조작 시작은 캔버스가
`onDragStart` / `onTransformStart` 로 알려주고, 그때의 트리가 "이전 칸"이 된다.

그 외:
- Transformer 는 width/height 가 아니라 scale 을 바꾼다. 그대로 두면 레이어 값과 화면이
  어긋나므로 scale 을 크기로 환산하고 1로 되돌린다.
- 핸들 크기는 캔버스 배율로 나눠서 넘긴다. 확대해도 화면상 같은 크기로 보여야 한다.
- 말풍선 12종을 모서리 반경·선 두께·점선으로 구분한다. 꼬리는 경로 도형이라 별도 작업이고
  `tail` 좌표 자리만 잡아 뒀다.
- 자동 저장 3초 디바운스. 저장 버튼은 두지 않는다.
- konva 는 `window` 를 써서 `dynamic(ssr:false)` 로 싣는다. 패널·툴바는 SSR 된다.

캔버스 안쪽 시각 규칙은 [편집기_캔버스_규칙.md](./편집기_캔버스_규칙.md) 에 따로 적었다.
디자인 가이드가 "react-konva 로 만들면서 정한다"고 미뤄 둔 항목이다.
