## 3. 새로 만든 것

### 생성 결과 저장 (마이그레이션 0006)

`storyboards`, `generation_jobs`, `cuts`, `post_packages` 와 Storage 버킷 `cuts`·`assets`(비공개).
워커가 쓰는 열(이미지 경로·잡 상태)은 사용자가 못 고치게 열 단위로 막았다. 서명 URL 은 `{owner}/`
경로만 발급한다. 자세한 이유는 `supabase/README.md`.

생성 영역에도 플랫폼처럼 목/Supabase 두 구현을 두었다(`src/features/generation/data/`).
`npm run dev:mock` 으로도 콘티 → 생성 → 편집 → 게시가 한 바퀴 돈다.

### 온보딩 캐릭터 시트 (PRD 1.1)

셀카 또는 특징 태그 → 캐릭터 시트 7장(정면·측면·표정 4종·전신) → "나" 캐릭터 에셋 → 새 시리즈의
고정 에셋. 고른 그림체가 시리즈 규칙이 된다. 셀카 원본은 시트를 만든 뒤 지운다(보관을 켠 경우만 남김).
`ImageGenerator.generateCharacterSheet()` 를 계약에 추가했고 지금은 목 생성기가 그린다.

### 콘티 (PRD 2.2)

처음 열면 바로 만들고, 편집(순서·추가·삭제·대사·후킹·CTA)은 1.5초 뒤 자동 저장. 실제 등장인물 이름과
시리즈 규칙(그림체·비율)을 보여준다. 사연이 비었거나 막히면 그 자리에서 고쳐 다시 만든다.

### 편집기 (PRD 3.2)

- 처음 여는 컷: 생성 이미지를 잠긴 배경으로, 콘티의 후킹·대사·나레이션·CTA 를 벡터 레이어로 얹는다
- 말풍선 꼬리(쐐기·생각 방울) + 끝점 핸들, 말풍선을 끌면 꼬리도 따라옴
- 스냅 가이드(캔버스 중앙·가장자리, 다른 레이어 변·중심)
- 두 손가락 핀치·Ctrl+휠 확대(보기 배율만)
- 작품 안 한글 글꼴 31종(전부 OFL). 목록은 `docs/편집기_캔버스_규칙.md`

### 게시물 패키지 (PRD 4.1) — `/episodes/:id/publish`

- 본문 3안(짧게·감성·유머), 해시태그 15~25개(시리즈 고정 / 이번 화 구분), 첫 댓글. 원클릭 복사, 고친 내용 자동 저장
- 캐러셀 PNG ZIP(1:1·4:5). 편집기와 같은 렌더러라 화면과 같다
- 모든 PNG 에 AI 생성 메타데이터(tEXt, IPTC DigitalSourceType). 무료 요금제 워터마크
- "인스타에 올렸어요" → 회차 `published` → 운영 깔때기 "첫 게시"

### 그 밖에

- 에셋 레퍼런스 이미지 업로드와 썸네일(PRD 2.1)
- 회차가 쓴 에셋을 `asset_references` 에 남김 → 에셋 화면의 "이 에셋을 쓰는 회차"가 실제 값
- 사용자별 동시 생성 3화 제한(PRD 비기능)
- 서버 재시작으로 워커를 잃은 잡은 다시 열 때 잡혀 있던 hold 를 환불하고 실패로 돌린다
- 첫 화 결과 화면이 실제 컷 이미지를 보여주고 게시 준비로 이어진다
- DB 타입을 `supabase gen types` 로 뽑는다(`database.generated.ts`). 손으로 쓴 타입은 별칭만 남겼다

### 알고 있는 한계

- 목 생성기 이미지는 자리표시자다. 캐릭터 시트를 레퍼런스로 넘기는 경로는 붙어 있지만 목은 쓰지 않는다
- 회전한 말풍선의 꼬리는 회전을 따르지 않는다
- 서명 URL 은 1시간짜리다. 편집기를 한 시간 넘게 열어 두면 이미지가 안 보일 수 있다(새로고침하면 된다)
- 오래된 hold 를 정리하는 배치는 없다. 재시작한 잡은 다시 열 때 환불되지만, 아무도 다시 열지 않으면 hold 가 남는다
