## 2. 남은 일 — 순서대로

상세와 코드 예시는 `docs/핸드오프_생성파이프라인.md`.

### 1순위 · `ImageGenerator` 자리표시자 구현

인터페이스만 있고 구현체가 없어 **이미지가 아예 나오지 않는다.** 모델 선정(오픈 이슈 1)을 기다리지 말고
컷 번호와 대사가 찍힌 이미지를 지연 시간까지 흉내내는 것을 먼저 만든다. 실패를 확률로 섞으면(예: 10%)
실패 경로까지 같이 본다.

이게 있어야 확인되는 것 — 컷 단위 진행률이 실제로 차오르는가, 실패 컷 재시도가 큐에서 도는가,
크레딧 hold → commit / refund 가 실제 흐름에서 맞물리는가. **생성 실패와 환불이 분쟁 나는 지점**이라
모델 없이 먼저 검증해 두는 값이 크다. 모델이 정해지면 이 구현만 갈아끼운다.

### 2순위 · 크레딧 호출 붙이기

생성 버튼이 "6크레딧"이라고 표시만 하고 원장을 부르지 않는다.
`holdCreditAction` / `commitCreditAction` / `refundCreditAction`이 `@/features/platform/actions`에 준비돼 있다.
부족하면 `code: "insufficient"`로 돌아오니 버튼을 막지 말고 `CreditSheet`를 연다.

### 3순위 · 콘티·생성 화면을 회차 컨텍스트에 연결

지금은 무엇을 입력하든 고정된 목 사연("퇴근 10분 전에…")이 나온다.
`loadEpisodeContext(episodeId)`가 `{ story, cutCount, rule, assets, seriesTitle, number }`를 준다.
`MOCK_STORYBOARD`를 이걸로 바꾸면 사용자가 실제로 쓴 사연으로 콘티가 만들어진다.

### 4순위 · 게시물 패키지 화면 (4.1)

**코드에 화면 자체가 없다.** 캡션 3안(짧게·감성·유머), 해시태그 15~25개(시리즈 고정 + 화별 동적 구분),
첫 댓글, 캐러셀 ZIP 내보내기. 시리즈 고정 해시태그와 말투는 `ctx.rule.fixedHashtags` `ctx.rule.tone`에 있다.

**여기까지 있어야 "인스타에 올릴 파일을 받는다"가 완성되고 첫 게시 완주율을 잴 수 있다.** 클로즈드 베타 범위다.
