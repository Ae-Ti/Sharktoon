# 테스트 두 가지

목 테스트와 실 테스트를 따로 돌릴 수 있다. 화면 코드는 같고 데이터 출처만 다르다.

| | 명령 | 데이터 | 언제 |
|---|---|---|---|
| **목** | `npm run dev:mock` | 메모리 목 저장소 | 화면·흐름·문구를 볼 때. 준비물 없음 |
| **실** | `npm run dev:real` | 로컬 Supabase(Postgres + Auth) | RLS·크레딧 원장·실제 쓰기를 볼 때 |

`npm run dev` 는 자동이다 — `.env.local` 에 Supabase 키가 있으면 실, 없으면 목.
`NEXT_PUBLIC_DATA_SOURCE=mock|supabase` 로 강제한다.

화면 위에 **"Supabase 미연결 · 목 데이터로 보고 있어요"** 띠가 뜨면 목으로 도는 중이다.

## 목 테스트

```bash
npm run dev:mock
```

새로고침하면 상태가 초기화된다. 목이라 그걸로 충분하다.

동작 검증은 명령 두 개로 돈다. CI 에서도 같은 걸 돌린다.

```bash
npm run check:repo        # 플랫폼: 에셋·시리즈·회차·크레딧·출석
npm run check:generation  # 생성: 콘텐츠 필터·편집 이력·콘티·레이어·게시물 패키지·PNG 메타데이터·파이프라인
```

목 생성기는 4컷째를 첫 시도에만 일부러 실패시킨다(실패·환불·재시도 화면을 보려고).
끄려면 `SHARKTOON_MOCK_FAIL_CUTS=` 로 비운다.

## 실 테스트

**Supabase 계정도 심사도 필요 없다.** 로컬에 전체 스택을 띄운다. Docker 만 있으면 된다.

```bash
# 1. Docker Desktop 실행 (한 번)

# 2. 로컬 Supabase 기동 — 처음 한 번은 이미지를 받느라 몇 분 걸린다
npm run db:start
```

출력에 나오는 `API_URL`, `ANON_KEY`, `SERVICE_ROLE_KEY` 를 `.env.local` 에 넣는다.
서비스 롤 키가 없으면 이미지 생성이 돌지 않는다 — 크레딧 정산과 컷 저장이 서버 전용 키로만 된다.

```bash
cp .env.example .env.local
# NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:54321
# NEXT_PUBLIC_SUPABASE_ANON_KEY=<출력된 ANON_KEY>
# SUPABASE_SERVICE_ROLE_KEY=<출력된 SERVICE_ROLE_KEY>
# CRON_SECRET=<아무 긴 문자열>
```

로컬에서는 크론을 안 걸어도 된다. 생성은 요청 직후와 진행률 폴링에서 작업자가 돈다.
크론 라우트를 손으로 돌려 보려면:

```bash
curl -X POST -H "Authorization: Bearer $CRON_SECRET" localhost:3000/api/queue/run   # 남은 생성 처리
curl -X POST -H "Authorization: Bearer $CRON_SECRET" localhost:3000/api/cron/daily  # 만료·탈퇴 정리
```

```bash
# 3. 마이그레이션 적용
npm run db:reset

# 4. 실제 경로로 실행
npm run dev:real
```

### 로그인

카카오·구글 OAuth 앱이 아직 없으므로 로컬에서는 **로그인 화면 아래 "개발용 이메일 로그인"** 을 쓴다.
가입을 누르면 바로 계정이 생기고(로컬은 이메일 확인이 꺼져 있다) 가입 트리거가 프로필과 8크레딧을 만든다.
이 블록은 프로덕션 빌드에 포함되지 않는다.

### 운영 화면 보기

`/admin` 은 `profiles.is_admin` 이 true 인 계정에만 열린다. 가입한 뒤 한 줄 실행한다.

```bash
psql postgresql://postgres:postgres@127.0.0.1:54322/postgres \
  -c "update profiles set is_admin = true"
```

### 실 테스트에서 확인할 것

목에서는 확인되지 않는 것들이다.

- 가입 트리거가 실제로 프로필과 8크레딧을 만드는가
- 다른 계정의 시리즈·에셋이 보이지 않는가 (RLS)
- 크레딧이 `hold → commit / refund` 로 움직이고 원장 합계가 잔량과 맞는가
- 출석이 하루 한 번만 되고 7일째 보너스가 붙는가
- 에셋을 참조하는 회차가 있을 때 삭제가 막히는가
- 온보딩에서 셀카·태그로 만든 캐릭터 시트 7장이 `assets` 버킷에 들어가고, 셀카 원본은 지워지는가
- 생성 전에 잔량을 보고 모자라면 충전 시트가 뜨는가(시작하고 나서 실패하지 않는가)
- 컷 이미지가 `cuts` 버킷에 들어가고, 진행률이 끝까지 가고, 회차가 `ready` 로 바뀌는가
- 편집기에서 고친 레이어가 새로고침 뒤에도 남는가
- 게시 화면에서 ZIP 이 받아지고(서명 URL CORS), "올렸어요" 뒤 운영 깔때기의 "첫 게시"가 오르는가
- 다른 계정 토큰으로 `credit_refund` 를 부르면 42501 로 막히는가
- 생성 중 서버를 꺼도(`generation_tasks` 에 할 일이 남는다) 다시 켜고 `/api/queue/run` 을 부르면 마저 되는가
- `/settings` 에서 크레딧이 종류별로 보이고, 운영자가 `/admin` 에서 수동 지급하면 환불 견적이 생기는가
- 환불 신청 → 운영자 승인 → 유료 크레딧이 빠지고 원장 합계가 맞는가
- 탈퇴 요청 → 철회가 되는가. 유예일을 지난 것으로 바꾸고 `/api/cron/daily` 를 부르면 계정과 파일이 지워지는가

### 한 바퀴 (약 3분)

로그인 → 캐릭터(태그) → 사연(4컷) → 콘티에서 후킹·CTA 고르기 → 이미지 생성(4컷째 실패) →
실패한 컷만 다시 → 첫 화 결과 → 편집기에서 말풍선 끌기·글꼴 바꾸기 → 게시 화면에서 ZIP·"올렸어요" → `/admin`

### 정리

```bash
npm run db:stop
```

## DB 타입 다시 뽑기

스키마를 바꾸면 타입도 같이 맞춘다. 지금은 손으로 쓴 것이 들어 있다.

```bash
npm run db:types
```

## Docker 없이 SQL 만 볼 때

로컬 Postgres 만으로 마이그레이션과 RLS 를 검증할 수 있다. `supabase/README.md` 참고.
